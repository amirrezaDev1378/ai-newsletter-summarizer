## 🔓 Attacks & Vulnerabilities

### [Bitget Hack Timeline: How Its Own System Approved a $387 Million Theft (2 minute read)](https://tracking.tldrnewsletter.com/CL0/https:%2F%2Ffinance.yahoo.com%2Fmarkets%2Fcrypto%2Farticles%2Fbitget-hack-timeline-own-system-164015015.html%3Futm_source=tldrinfosec/1/010001a0e82b6d96-4905840e-0130-41c9-9ec6-9966f9327e1f-000000/BUOp75kLzgU_N0i8dgv27bLCpt83kxkyP4VJhbvbtQM=452)
On September 24, attackers stole $387.5 million from Bitget's hot and warm wallets by feeding false transaction data into a compromised backend system, which authorized the transfers. Bitget detected unauthorized activity at 18:31 UTC, paused withdrawals hours later, and ruled out private-key theft. Mandiant and SlowMist are investigating, and CEO Gracy Chen has flagged possible North Korean involvement.

### ['Salesbleed' Exploits Salesforce Agents to Enable Slack Phishing (4 minute read)](https://tracking.tldrnewsletter.com/CL0/https:%2F%2Flinks.tldrnewsletter.com%2FJlEYnl/1/010001a0e82b6d96-4905840e-0130-41c9-9ec6-9966f9327e1f-000000/XIru_FuFcYCEeW2MCdolfH7myB5eT7buriT-CV2rR2U=452)
Zenity identified three Salesforce Agentforce weaknesses allowing attackers to inject commands via Web-to-lead forms and bypass URL filters. If connected to Slack, they could post phishing links in internal threads that appeared to come from employees or IT. Salesforce has added confirmation prompts, spec-compliant URL parsing, and centralized URL inspection to mitigate this.

### [Cloudflare fixes Containers cross-tenant flaw exposing customer data (8 minute read)](https://tracking.tldrnewsletter.com/CL0/https:%2F%2Fblog.cloudflare.com%2Fcontainers-cross-tenant-vulnerability%2F%3Futm_source=tldrinfosec/1/010001a0e82b6d96-4905840e-0130-41c9-9ec6-9966f9327e1f-000000/GDVD67MyFQ-XBGdiDMgawtKYqI3JiaKDVLAlSJkEhqQ=452)
Cloudflare remediated a cross-tenant flaw in Containers and Sandboxes that allowed Workers Paid customers to read residual disk blocks left by other tenants on the same host. The issue stemmed from dm-thin storage pools running with `skip_block_zeroing`. Cloudflare removed `skip_block_zeroing` fleet-wide, retired running container disks, and cleared cached image snapshots by September 19.

## 🧠 Strategies & Tactics

### [EDR Evasion: Process Injection Without WriteProcessMemory (4 minute read)](https://tracking.tldrnewsletter.com/CL0/https:%2F%2Fwww.zerosalarium.com%2F2026%2F09%2Fedr-evasion-process-injection-without-WriteProcessMemory.html%3Futm_source=tldrinfosec/1/010001a0e82b6d96-4905840e-0130-41c9-9ec6-9966f9327e1f-000000/gv1MvtQc9MT48eX2zyoLeK8bvOC5M4zn8Mfeu3JFGNY=452)
Zero Salarium details a remote process injection technique that bypasses the VirtualAllocEx and WriteProcessMemory pair by spawning an interactive console child and writing shellcode into its memory via WriteFile on the child's hStdInput pipe. Defenders should monitor for VirtualProtectEx against remote processes, read/write activity on named pipes, and console command-storage memory regions.

### [Galileo's first civil authenticated position fix under spoofing conditions (3 minute read)](https://tracking.tldrnewsletter.com/CL0/https:%2F%2Fwww.esa.int%2FApplications%2FSatellite_navigation%2FGalileo%2FGalileo_s_first_civil_authenticated_position_fix_under_spoofing_conditions%3Futm_source=tldrinfosec/1/010001a0e82b6d96-4905840e-0130-41c9-9ec6-9966f9327e1f-000000/5v9GDrw_Waah558wRx0XQ84SgANqgltfuMxywyDgKrI=452)
Galileo demonstrated its first real-world civil position fix using the upcoming Signal Authentication Service (SAS) during live spoofing tests in Norway. SAS encrypts spreading codes and publishes decryption keys on a delayed channel, letting receivers confirm pseudoranges post-facto. 

### [OAuth token abuse: how the attack works and how to stop it (7 minute read)](https://tracking.tldrnewsletter.com/CL0/https:%2F%2Fwww.scworld.com%2Ftech-explainer%2Foauth-token-abuse-how-the-attack-works-and-how-to-stop-it%3Futm_source=tldrinfosec/1/010001a0e82b6d96-4905840e-0130-41c9-9ec6-9966f9327e1f-000000/Al_o1_-w7w4dUcniBSHKPBm1GtelbuKGX4hcATr8o8k=452)
OAuth token abuse bypasses password resets and MFA because tokens belong to applications rather than users. Organizations should monitor Entra ID audit logs for consent grants, restrict user consent to verified low-impact apps, require admin approval for high-risk scopes, and maintain an approved application inventory.
