# How the Math Used in 19th-Century Heat Physics Helps LLMs Understand Sentences

![Heat to LLM physics concept](https://substackcdn.com/image/fetch/$s_!lxN_!,w_1100,c_limit,f_auto,q_auto:good,fl_progressive:steep/https%3A%2F%2Fsubstack-post-media.s3.amazonaws.com%2Fpublic%2Fimages%2F7f61f39a-8b42-4ee5-a4c4-74f54026e82f_3034x1802.png)

In 1822, Joseph Fourier published his work on how heat spreads through materials. One of his key mathematical tools was a way to represent complicated temperature patterns using combinations of sine and cosine functions. Nearly two centuries later, those same functions appear inside a very different technology: the transformer architecture behind modern language models.

The applications seem to be quite far apart. Fourier studies temperature across a physical object. On the other hand, a language model processes tokens arranged in a sequence. Yet, sine and cosine functions provide a useful structure in both settings.

This is because sine and cosine functions can turn positions into structured numerical patterns. A transformer model can then use those patterns to learn how the order of words affects their meaning. The waves supply position information. The model’s training teaches it how to use that information.

## The Physics Behind Heat Measurement and LLMs

In the early nineteenth century, Joseph Fourier studied how heat spreads through materials.

Consider a metal bar with some sections hotter than others. In order to predict how its temperature changes, we need a way to describe that temperature pattern mathematically. Fourier developed methods to represent complicated patterns as combinations of simpler sine and cosine functions. Eventually, these functions became the key tools for studying heat, vibrations, sound, and many other physical phenomena.

![Sine and cosine wave representation](https://substackcdn.com/image/fetch/$s_!hgTN!,w_1100,c_limit,f_auto,q_auto:good,fl_progressive:steep/https%3A%2F%2Fsubstack-post-media.s3.amazonaws.com%2Fpublic%2Fimages%2F30684304-c503-4ee7-ba11-01a819a6faf5_3844x1460.png)

For reference, a sine wave is a smooth, repeating pattern. Combining waves that repeat at different rates creates a way to describe much more complicated patterns. For example, a broad temperature variation might require slowly changing components, while smaller variations require faster ones. The temperature itself doesn’t have to oscillate over time. A wave can describe how temperature varies across space at a particular moment.

Similarly, in the field of LLMs, the mathematical input doesn’t have to represent time or physical distance. It can represent a token’s position in a sequence.

Though sine and cosine functions predate Fourier, the 19th century saw their greater use in mathematical physics. Positional encoding, which is a critical way in which LLMs interpret word order, also belongs to the same mathematical family.

## How Word Order Carries Information

Word order carries information that the words alone cannot provide. Consider these two sentences:

```
Alice trusts Bob.
Bob trusts Alice.
```

Both contain the same words. Their meanings are different because the positions of the names determine who trusts whom.

Software has the same requirement. The expressions `income - expenses` and `expenses - income` contain the same variable names and operator, but generally produce different results.

Therefore, a language model needs access to two kinds of information: which tokens appear, and how those tokens are arranged. Just recognizing the vocabulary only provides part of what is needed to interpret the sequence.

This becomes especially clear with repeated words. In “very, very difficult,” both occurrences of “very” have the same identity, but they occupy different places. A useful representation of this sentence must allow the model to distinguish those two occurrences of the same word.

## How Does a Model Understand Words

A model starts by turning text into numbers. Since a neural network performs calculations on numbers, the text has to first pass through a process called tokenization. A token can be a word, part of a word, punctuation, or another text fragment.

![Tokenization process](https://substackcdn.com/image/fetch/$s_!c8Ed!,w_1100,c_limit,f_auto,q_auto:good,fl_progressive:steep/https%3A%2F%2Fsubstack-post-media.s3.amazonaws.com%2Fpublic%2Fimages%2F85789cb8-fb32-43b2-b76a-fcc7ef79fdc5_3306x1288.png)

Each token receives an identifier. The model uses that identifier to look up an embedding, which is a list of learned numbers (a vector). An embedding might look like this:

`[0.20, -0.40, 0.70, 0.10]`

Actual embeddings usually contain many more numbers. Their values are adjusted during training so that they become useful for the model’s tasks. Individual numbers generally do not have tidy meanings such as “this is a noun” or “this refers to a person.”

At the initial lookup stage, the same token identifier retrieves the same embedding wherever it appears. The embedding for a token doesn’t automatically change just because that token occupies position 2 instead of position 20.

Later layers build representations that incorporate context. But at the beginning, the model still needs a way to connect token identity with location.

## How the Attention Mechanism Makes Sense of the Order

Basic attention doesn’t automatically use the order of the list. Transformers rely heavily on a mechanism called attention.

Attention lets each token gather information from other tokens by calculating how strongly to weight their contributions. For example, processing a pronoun may require information from a name that appeared earlier. Attention provides a way to connect those pieces of text.

Let’s now consider the simplest case. Attention can examine every token, and there is no positional information or other mechanism that indicates order. For the token “trusts,” both example sentences provide the same surrounding token identities: “Alice” and “Bob.” Swapping those names changes their locations, but the basic attention calculation has no position feature telling it which name comes first.

More precisely, reordering the input reorders the corresponding output representations. But the reordering doesn’t independently recognize the new grammatical relationships created by the rearrangement. This is the order problem that positional representations address.

One objection is that the tokens already occupy different array indexes. Why cannot the model simply use those indexes?

This is because an array’s layout doesn’t automatically become an input feature. A program that sums an array receives an ordered structure, but its calculation produces the same answer even after the elements are rearranged. Order can make a difference only when the computation actually uses it. In other words, basic attention needs a way to make the sequence structure affect its calculations.

## How Location of the Words is Made Available to the Model

Positional encoding is the technique that is used to make the location of the words available to the model. A positional encoding converts a location in a sequence into a numerical representation.

For example, in the first sentence, Alice is at position 0, trusts at position 1, and Bob at position 2. On the other hand, in the second sentence, Bob is at position 0, trusts is at position 1, and Alice is at position 2.

![Positional sequence mapping](https://substackcdn.com/image/fetch/$s_!Vn65!,w_1100,c_limit,f_auto,q_auto:good,fl_progressive:steep/https%3A%2F%2Fsubstack-post-media.s3.amazonaws.com%2Fpublic%2Fimages%2F51c57323-b67b-4bea-bcfd-4c9fbb256d66_3034x1802.png)

The word “Alice” retains its token identity, even while its position changes. The same for “Bob”. The model can now receive different combinations of content and position for the two sentences.

The immediate question is how to represent those positions.

We can give the model integers such as 0, 1, and 2 as input. Those numbers contain the necessary ordering information. Sine waves don’t add information that the position number lacks. Their purpose is to express that information in a form with useful numerical structure.

For instance, naively adding the number 10000 to every component of an embedding could overwhelm the token’s existing values. More generally, a single scalar requires the model to construct whatever positional features it needs from that one number.

A collection of sine and cosine values supplies several structured features directly. Their values remain bounded, and different components change at different rates as positions increase.

## The Use of Sine and Cosine Functions

Sine and cosine describe movement around a circle. A simple explanation involves a hand rotating around a circle. Imagine a circle centered at zero with a radius of one. A hand starts by pointing to the right and turns counterclockwise.

The horizontal coordinate of its tip is the cosine of its angle. The vertical coordinate is the sine.

As the hand turns, its height rises, falls, becomes negative, and returns to its starting point. Plotting that height against the angle produces a sine wave. The horizontal coordinate produces a cosine wave. Both coordinates remain between −1 and 1.

To use this idea for positions, let each step forward in the token sequence rotate the hand by a fixed amount. Position 0 has one pair of coordinates, position 1 has another, and so on.

Why do we use both coordinates? Because a height alone can correspond to two different places on the circle. A point on the upper-left side and a point on the upper-right side can have the same height. Their horizontal coordinates distinguish them.

Together, sine and cosine describe the hand’s orientation within a complete turn. However, after one full turn, both readings repeat, which leads to the need for multiple rotation speeds.

## Why Multiple Rotation Speeds Are A Better Choice

One rotating hand cannot distinguish positions separated by a complete cycle. If it returns to its starting point every eight tokens, positions 0 and 8 have identical readings.

![Rotation speeds diagram](https://substackcdn.com/image/fetch/$s_!qz9G!,w_1100,c_limit,f_auto,q_auto:good,fl_progressive:steep/https%3A%2F%2Fsubstack-post-media.s3.amazonaws.com%2Fpublic%2Fimages%2Fffae8c01-5484-4471-8159-a4f4aaee0150_3502x1554.png)

Now imagine three hands with different speeds. The first completes a turn every eight token positions, the second every 32, and the third every 128. At position 8, the fastest hand returns to its starting orientation. The other two have different readings from their readings at position 0. Their combined coordinates still distinguish those positions.

The combined position code consists of all six numbers: a sine and cosine value for each speed. More pairs provide more components that change at different rates.

The original transformer uses this general construction, with a particular mathematical schedule of frequencies. Faster components change substantially over short distances, while slower components vary across longer stretches.

## How is the Position Code Used

The original transformer adds the position code to the token embedding. In the 2017 paper *Attention Is All You Need*, the position encoding has the same number of components as the token embedding. Corresponding components are added together before the sequence enters the transformer layers.

`InputRepresentation = TokenEmbedding + PositionEmbedding`

For a small illustrative embedding, the addition at position zero could look like this:

* Token embedding: `[0.20, -0.40, 0.70, 0.10]`
* Position-zero encoding: `[0.00,  1.00, 0.00, 1.00]`
* Combined input: `[0.20,  0.60, 0.70, 1.10]`

The alternating zeros and ones arise because sine is zero and cosine is one at angle zero.

Moving the same token to another position changes the position encoding, which changes the combined input. Placing a different token at the same position changes the token embedding. This gives the transformer a representation influenced by both identity and location.

Furthermore, sine and cosine pairs provide a regular way to represent movement between positions. Advancing by a fixed number of positions always rotates each pair by a fixed angle for that frequency. Mathematically, a fixed linear transformation can map a sinusoidal position code to the code at a fixed offset.

## How Training Uses the Position Information

Training turns position information into useful language behavior. Knowing that a name appears before a verb does not, by itself, explain what the sentence means.

Consider these examples:
* Alice trusts Bob.
* Alice is trusted by Bob.

Alice appears first in both, but the relationship changes. An adequate model must consider the verb form and the surrounding words as well as their positions.

![Training context illustration](https://substackcdn.com/image/fetch/$s_!aasl!,w_1100,c_limit,f_auto,q_auto:good,fl_progressive:steep/https%3A%2F%2Fsubstack-post-media.s3.amazonaws.com%2Fpublic%2Fimages%2F4b6d200a-52ef-4f05-8c72-7cb0977630b0_3632x1814.png)

During language-model training, the system repeatedly tries to predict text. Its parameters are adjusted when its predictions are poor. Over many examples, a model can learn relationships involving subjects and verbs, modifiers and nouns, negation and statements, or opening and closing brackets in code. 

Positional encoding makes order available to this learning process. Attention helps connect relevant tokens, and other learned transformations process the resulting information.

## How Rotary Position Embeddings Work

Rotary position embeddings (RoPE) reuse the same mathematics inside attention, introducing position in ways other than simply adding a vector to the input embedding.

![RoPE architecture concept](https://substackcdn.com/image/fetch/$s_!rnBe!,w_1100,c_limit,f_auto,q_auto:good,fl_progressive:steep/https%3A%2F%2Fsubstack-post-media.s3.amazonaws.com%2Fpublic%2Fimages%2F55b0959e-5fbd-4f49-869c-b386e0f8ca47_3070x1684.png)

Attention compares numerical representations called queries and keys. A query helps determine what information a token gathers, while keys participate in calculating how strongly other tokens match.

RoPE groups components of these representations into pairs and rotates those pairs according to token position using sine and cosine functions. When attention compares a rotated query with a rotated key, the positional contribution depends on their relative rotation—which corresponds to their relative position.

## Other Methods Apart from Sine and Cosine Functions

While sine and cosine are useful choices, transformers utilize several alternative ways to obtain position information:

* **Learned positional embeddings:** Assigns each supported position a trainable vector adjusted via training.
* **ALiBi:** Modifies attention scores using a penalty proportional to the distance between tokens, introducing a preference for nearby context without adding sinusoidal vectors.
* **Causal masks:** Generative language models commonly use causal masks to prevent a token from attending to later tokens. This pattern provides structural information, allowing causal transformers to learn positional behavior even without explicit encoding.

## Conclusion

Ultimately, being able to calculate a position encoding for a very large position doesn’t mean a model can reliably understand an arbitrarily long document. A formula can produce a code for position one million, while the model may have little experience using such positions or relating tokens across such large distances. Memory and computation impose additional constraints.

However, mathematics developed long ago for describing physical patterns provides an effective numerical language for representing sequence position. Sine and cosine give that representation bounded values, multiple scales, and consistent relationships under shifts. Training then teaches the model how those positional relationships interact with the content of language.
